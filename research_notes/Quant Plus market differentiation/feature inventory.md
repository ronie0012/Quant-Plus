# Quant-Plus implemented product feature inventory

Scope: current checkout at `HEAD` `2dc0898` (`feat: harden InsForge cutover and workspace flows`), inspected on 2026-10-17. This inventory describes behavior evidenced by current source, route wiring, server code, tests, and current status/startup documents. `Implemented` means a user-facing path exists in the checkout and has relevant code or verification; it does not mean that an external provider is currently configured, that a roadmap gate has passed, or that an empirical quality claim is established.

Status labels used below:

- **Implemented** — a user can reach the workflow in the current checkout and the implementation has a concrete handler/data path.
- **Partial / conditional** — the workflow exists but depends on a provider, model, data coverage, or a narrower scope than the surrounding product language suggests.
- **Unavailable / gated** — the route or code explicitly refuses, disables, or marks the capability unavailable.
- **Local / hosted** — identifies where the current behavior is authoritative. The local runtime is the default; hosted InsForge support is implemented behind explicit activation flags but has not replaced the local runtime.
